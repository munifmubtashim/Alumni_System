# app/

**Purpose:** the application root:

- `App.tsx`: renders `RouterProvider` from `react-router/dom`, not `react-router`, so logout's `flushSync` navigation works (gotcha G08).
- Providers for TanStack Query and Jotai, and the shared `QueryClient`.
- The router: the path-less `RootLayout` holds two shells. `AuthShell` wraps `GuestOnly` → `/login`, `/register`; `AppShell` wraps `RequireAuth` → `/` (Home), `/directory`, `/alumni/:id`, `/feed`, `/me` and, inside a nested `RequireAdmin`, `/admin` (REQ-015: a non-admin gets `ForbiddenPage`, the 403 page, and the admin chunk never loads), plus the public `/about` (outside `RequireAuth`, REQ-014), the unknown-path route and test pages. `AppShell` ends with `SiteFooter` (© brand, About, Contact) under every page. All three guards come from `features/auth`.
- Lazy routes (ADR-08), six of them: `/directory` (`DIRECTORY_ROUTE`), `/alumni/:id` (`PROFILE_ROUTE`), `/feed` (`FEED_ROUTE`, REQ-009), `/me` (`ME_ROUTE`, REQ-010), the public `/about` (`ABOUT_ROUTE`, REQ-014) and the admin-only `/admin` (`ADMIN_ROUTE`, REQ-015) are loaded with the route's `lazy`, so each page is its own chunk. Only the route's dynamic `import()` may reference `features/directory`, `features/profile`, `features/feed`, `features/me`, `features/about` or `features/admin`; an ESLint rule (`@typescript-eslint/no-restricted-imports` in `eslint.config.js`; `import type` is allowed) rejects a static import of any of them anywhere else in `src/` except tests, and `lazyRoutes.test.ts` scans every non-test file in `src/` as a second check. Both checks run once per feature, leaving out only that feature's own folder, so the lazy features cannot import each other. A new large page is added to the `LAZY_FEATURES` list in both places.
- `HydrateFallback`: the "Loading…" line shown in `<main>` while a lazy page's code loads on a direct visit. Set it as a static property of the lazy route object itself, never on the root or on what `lazy` returns: the router stops rendering at the nearest route that has one, so anywhere higher hides the shell. A client-side click to a lazy page shows no fallback (the old page stays until the code arrives). A chunk that fails to load shows the inner `RouteError`.
- `RootLayout`: applies the theme and mounts `SessionBridge` once for every page, auth pages included. Don't mount it in a shell.
- The `AuthShell` layout: no header, only the `ThemeToggle` in the top-right corner, and `<main id="main">`.
- The `AppShell` layout: the header holds the `Logo` (with `BRAND_NAME` from `@/config/brand`, linking home), `MainNav` (`<nav aria-label="Main">`, desktop only), the compact icon-only `ThemeToggle` (the one the login page uses) and `HeaderAuth` (Log in / Sign up for guests; for a signed-in user an avatar menu with their name and email, View profile (alumni only), Account settings, Admin settings (admins only, to `/admin`) and Log out). On phones (< 48rem) the nav is `BottomTabs` (`<nav aria-label="Main tabs">`, sticky at the bottom). Each reads its own list in `navItems.tsx`, which hold only pages that exist: `HEADER_NAV_ITEMS` (Home, Directory, Feed, Admin) for `MainNav`, and `TAB_NAV_ITEMS` (Home, Directory, Feed, Profile, Admin) for `BottomTabs` (REQ-016). Home is marked `end`, so it is current on `/` only. Profile is marked `own`: `navItemPath(item, alumniId)` sends it to the user's own `/alumni/<alumni_id>` (from `useCurrentUser()`), or to `/me` when they have no alumni profile (a student, an admin with none) or `['me']` has not loaded yet; it is current on that path only. Admin (shield icon, last in both lists as S6 draws it) is marked `adminOnly`; `visibleNavItems(items, useIsAdmin())` drops it for everyone else, so alumni and students see three links and four tabs, admins four links and five tabs. That filter only hides links: `RequireAdmin` and the API decide access (REQ-015). **Deliberate deviation from the design (REQ-012):** S1/S2/S3/S5 draw "My Profile" in the header nav; here `/me` is called Account settings and is left out of the header nav and the tab bar (reached from the avatar menu and Home's completeness card while the profile is incomplete; on phones also from the Profile tab when there is no alumni profile). The Home link and its house icon are not in S1 (REQ-016). The shell follows `docs/design/screens/app/S1-*`; `main` is full width with S1 gutters and each page caps its own width. `--page-max` (72rem, REQ-016) is declared once in `styles/global.css` `:root`, so it holds outside the shell too: Home, Directory, Profile, Feed and `SiteFooter`'s inner box use `min(100%, var(--page-max))` centred, the footer with the same side padding as `main`, so the footer lines up with the page (Account settings and About keep their own caps; Admin uses the full width, as S6 does).
- The route error element.

**May import:** anything in `src/` (`@/config/**`, `@/features/**` except `features/directory`, `features/profile`, `features/feed`, `features/me`, `features/about` and `features/admin`, which only their lazy route's dynamic import reaches, `@/components/ui/**`, `@/store/**`, `@/services/**`, `@/styles/**`).

**Imported by:** only `src/main.tsx`. Nothing else may import from `app/`.
