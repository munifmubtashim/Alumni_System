# features/admin/

**Purpose:** The admin page at `/admin` (REQ-015; design `docs/design/screens/app/S6-*`). Admins only: `RequireAdmin` (in `features/auth`) shows everyone else a 403 page, so this chunk never loads for them. The server stays the judge: a stale role that gets a 403 from `/api/admin/*` shows the normal error state, never a logout (ADR-03).

**What is here:**

- `AdminPage` — full width like S6 (the shell's padding only, no 72rem cap); the header row (h1 "Admin", focusable as the toast's focus fallback, and "Add alumni"), `AdminStats` and the alumni panel: `AdminSearch`, then `AlumniTable` (from 48rem) and `AlumniCardList` (below 48rem), both rendered from the same data and switched by CSS on wrappers that never use the `hidden` attribute (G18), then `AdminPagination`. Loading and loaded share one tree, so the table and its header buttons stay mounted when the first page arrives. States: skeleton rows/cards while the first page loads; `LoadError` (Alert + Retry); "No alumni match “q”" with Clear search (focus goes back to the search box); "No alumni yet". A page past the end (stale link, or a list that shrank) is replaced in place by the last page, with skeletons meanwhile. A visually hidden h2 "Alumni" (`tabIndex={-1}`) names the table and the card list and is the focus target after a row disappears.
- `AlumniDrawer` + `AlumniForm` — the S6 add/edit drawer on the `Drawer` primitive. Add: Full name, Email, University + Graduation year, Department, Current role + Company (pairs side by side from 48rem), Temporary password; footer Cancel / "Add alumni". Edit hides Email and Temporary password, starts from the row and saves with "Save changes"; the body is exactly the six editable fields (all sent; an empty one clears it). Errors show when a field is left or on submit, and the first invalid field gets focus. While saving, every control is disabled, a second click sends nothing and ×, Escape and the backdrop are ignored. Closing with typed input asks in the footer ("Discard this new alumni?" / "Discard changes?": Keep editing / Discard); Escape there goes back to editing, × and the backdrop leave the question up. After a save the drawer stays open until the table has refetched, then focus goes back to the opener if it is still on the page, else to the "Alumni" heading (also if a later refetch removes it). Toasts: "<name> added", "Changes saved", and on an edit 404 "This alumni no longer exists" (the drawer closes and the table refetches). A server error lands on its field (`adminErrors.ts`), else in a focused Alert. No form library: 8 flat fields, controlled state (ADR-04's revisit line is about 8 fields; this form doesn't need one).
- `DeleteAlumniDialog` — the S6 delete confirmation on the `ConfirmDialog` primitive (danger tone, trash icon): "Delete <name>?", "This permanently removes their profile, posts, and comments from <BRAND_NAME>. This action can't be undone." (brand from `config/brand.ts`, not S6's "Alumni Network"), Cancel / "Delete alumni". Focus starts on Cancel; Cancel and Escape send it back to the row's Delete button; the backdrop does nothing. While the delete runs the button is busy, a second click sends nothing and Escape / Cancel are ignored. On success the dialog stays until the table has refetched without the row, then closes with the toast "<name> deleted" and focus on the "Alumni" heading. A refusal (403 own account, 409, 5xx, network) keeps the dialog open with the message in a focused Alert (`deleteErrors.ts`); a 404 closes it with "This alumni no longer exists" and refetches. A delete that empties the last page lands on the new last page (the page's past-the-end step back). Delete is hidden on the row whose `user_id` is the signed-in admin's (from `useCurrentUser`); the server refuses it anyway.
- `useAdminToast` — the page's one success toast, the /me pattern (G36): always mounted, 4 s, paused on hover/focus, focus to the h1 if it closes under the user.
- `AdminStats` — four cards from `GET /api/admin/stats`: Total alumni, Students, Posts, Mentors available (row of four from 48rem, 2×2 below). Skeleton in each value while loading; an error with Retry in place of the cards. Its own query, so it never hides the table.
- `AlumniTable` — columns Name (a row header), Grad. year, Department, University, Mentor ("Yes"/"No") and the row actions. Name and Grad. year headers are buttons: the active one shows ↓ (ascending) or ↑ (descending) and carries `aria-sort`. A missing value shows "—", read out as "Not set". Only the table scrolls sideways (200% zoom).
- `AlumniCardList` — the phone cards: name, "year · department", the same two buttons.
- `RowActions` — the icon buttons "Edit <name>" and "Delete <name>". `onEdit` / `onDelete` get the row and the pressed button (a dialog can return focus to it). `canDelete={false}` hides Delete; `AlumniTable` and `AlumniCardList` take a `canDelete(row)` predicate for it.
- `AdminPagination` — "Showing <n> of <total>" (n = rows on this page, both formatted, a polite live region) and Prev / Next, disabled at the edges. When a click reaches an edge, focus moves to the other button once the new page renders.
- `AdminSearch` — the "Search alumni" box: debounced 300 ms, replaces the history entry, back to page 1. Same own-write guard as the directory's FilterBar (L-REQ-006-1).
- `mutations.ts` — `useCreateAlumni`, `useUpdateAlumni`, `useDeleteAlumni`: not optimistic; on success (and on an edit or delete 404) they refetch `['admin']` and wait for it, and mark `['alumni']` stale (the directory, real key, L-REQ-010-1); an edit and a delete also mark `['posts']` and `['feed']` stale (author names; a delete removes posts and comments and recounts other posts' comment counts).
- Hooks: `useAdminParams` (URL state: `setQuery` replace, `sortBy` / `setPage` / `clearSearch` push, `clampPage` replace; writes build on the last written URL); `queries.ts` (`useAdminStats` → `['admin', 'stats']`; `useAdminAlumni` → `['admin', 'alumni', params]`, `searchAlumni` with `sort`, `order` and `pageSize: 10`, `keepPreviousData` so header and paging buttons keep focus; `adminKeys.all` = `['admin']` for invalidation).
- Pure helpers: `deleteErrors.ts` (a failed delete: 404 → gone, other 4xx → the server's message, 5xx/network → "Couldn't reach the server"), `validation.ts` (the drawer's rules and messages, copies of the backend's `validateAdminAlumniFields`, `requiredEmail` and `validateNewPassword(…, "Temporary password")`, L-REQ-006-3; `isFormDirty`, the request bodies), `adminErrors.ts` (409 → Email on add, 404 → gone on edit, field-named 400 → that field by an explicit prefix table, G38), `params.ts` (parse and write `q` ≤ 100, `sort` name|graduationYear, `order` asc|desc, `page` 1..10000; defaults name/asc/1 are left out of the URL; copies of the backend limits, L-REQ-006-3), `formatCount.ts` (a module-level `Intl.NumberFormat('en-US')`), `rowText.ts` (name fallback, phone card line).
- `useDebouncedCallback.ts` — a copy of the directory's (lazy features can't import each other, L-REQ-008-6).
- `testKit.ts` — test-only helpers (fake API at the axios adapter, with optional write responders keyed "METHOD /url", render with router and query client); never imported by app code.

## Deliberate differences from S6

Recorded here and in the REQ-015 architecture (L-REQ-012-2):

- Stat labels are the user's four (Total alumni, Students, Posts, Mentors available), all in the plain text colour; S6's green/red accents and its "New this month" / "Pending verification" cards are not used.
- Sizes with no token take the nearest one: stat card padding `space-4` / `space-3` (S6 18px / 14px), table cells `space-3` `space-4` (S6 14px 16px), table header `space-1` `space-4` `space-2` (S6 0 16px 10px; the 4px top keeps the sort button's focus ring from being clipped), phone cards `space-3` `space-4` (S6 14px), title `heading-md` at every width (S6 22px / 18px), stat numbers `heading-lg` / `heading-md` (S6 26px / 20px), labels `caption`.
- No shadows (Stylelint bans them); hairline `border-subtle` borders, and one border colour for both S6's borders and its lighter row dividers.
- `accent` is the contrast-fixed token, darker than S6's accent (L-REQ-004-2); the footer count is `ink-secondary`, not S6's `ink-muted` (muted text is below 4.5:1).
- Prev / Next and the count also show on phones (S6 phone has none). Phones can't sort (S6 phone has no headers either).
- Row action buttons are 32px squares (S6 about 27px) with a 44px hit area from a `::before`, and a 12px gap between the two so the hit areas meet without overlapping (G35). Desktop rows land about 57px (S6 about 59px), phone cards about 64px (S6 about 62px).
- The search box and the drawer's inputs are the shared `SearchField` / `Input` primitives (sunken background, 16px text, their own label style), as on every other form; 16px text also stops iOS zooming on focus.
- The drawer's and the dialog's backdrop covers the header too (S6 starts it below the header); the header can't be used while either is open anyway.
- Help text under Temporary password (S6 has none).
- The shell stays as built: brand "Alma", no "My Profile" header link (REQ-012), phone tab "Account" not "Profile".
- Drawer: a Temporary password field, no Role select, "Current role" and "Company" as two fields, an "Edit alumni" mode (S6 draws only Add), the discard question in the footer, full width on phones (S6 has no phone drawer).
- Delete dialog: brand text via `BRAND_NAME` ("…from Alma.", not "…from the Alumni Network."); no shadow (a `border-subtle` hairline); sizes per the `ConfirmDialog` primitive's notes.

**May import:** `@/components/ui/**`, `@/config/**`, `@/services/**`, `@/features/auth` (its public `index.ts`), and types from `@alumni/shared`. Not `@/app/**`. Not another lazy feature (`directory`, `profile`, `feed`, `me`, `about`).

**Imported by:** only the lazy route's dynamic `import()` in `app/router.tsx` (ADR-08). There is no `index.ts`; nothing else may import this folder statically.
