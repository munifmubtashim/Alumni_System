## Approach

- `generate-tokens.ts` exports `renderTokensCss(tokens): string` (pure) and, when run directly (`import.meta.main` or argv check), reads `../../docs/design/design-system/tokens.json` relative to the script and writes `src/styles/tokens.css`. `--check` flag compares and exits 1 if different (for `tokens:check`). **Units:** spacing and type sizes/line-heights are converted from the JSON's px to rem (px ÷ 16, e.g. `--space-4: 1rem`, body `1rem/1.625rem`) so text and spacing follow the user's browser font-size setting; radii stay px. Output shape exactly as architecture.md → Design tokens: `:root` for spacing/radius/font/type (`--text-<name>: <weight> <size>/<lineHeight> var(--font-sans)` plus `--text-<name>-size`, `-line`, `-weight`); `:root, :root[data-theme='light']` and `:root[data-theme='dark']` for colors with `color-scheme`. Stable ordering (JSON order) so output is deterministic. Header comment "Generated from docs/design/design-system/tokens.json by scripts/generate-tokens.ts — do not edit."
- `global.css` (no `@import` — the font and `tokens.css` are imported from `main.tsx`, which is what makes the tokens reach the browser): box-sizing reset, `margin: 0` on body, body `background: var(--surface-page); color: var(--ink-primary); font: var(--text-body);`, headings reset, `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }`, `@media (prefers-reduced-motion: reduce)` disabling transitions. Font family token should prefer `'Inter Variable'` — the generator maps the JSON's `'Inter'` family to `'Inter Variable', 'Inter', …` (note this in a comment).
- `contrast.test.ts` (`// @vitest-environment node`): reads `tokens.json`, computes WCAG contrast for the text/surface pairs the primitives actually use, in both themes, and asserts ≥4.5:1 (text) / ≥3:1 (UI boundaries only where listed). The pair list and any accepted exceptions are exactly those in architecture.md → Contrast; an exception must be listed there with its ratio, so a token change that worsens contrast fails the test.
- `scripts/generate-tokens.test.ts` (was `src/styles/tokens.test.ts`; `// @vitest-environment node`): renders from the real JSON and `expect(rendered).toBe(readFile(tokens.css))` with a message "tokens.css is stale — run npm run tokens"; asserts each color token name appears in both theme blocks, and each spacing/radius/type token appears once.

## Notes

### Implementation notes (2026-10-05)

- **Test lives in scripts/ (rework, user-approved).** First pass put it at `src/styles/tokens.test.ts`, which made `tsconfig.app.json` (no Node types) typecheck the generator, forcing a `process.getBuiltinModule` workaround. Moved to `scripts/generate-tokens.test.ts` (covered by `tsconfig.node.json` and the Vitest include); the generator now uses plain `node:fs`/`node:path`/`node:url` imports and runs its CLI only when `process.argv[1]` is this file.
- **Vitest blanks CSS imports.** `import css from './tokens.css?raw'` returns `''` under Vitest (CSS is stubbed unless `test.css.include` matches). So the generator exports `readTokensCss()` and the test compares that with `renderTokensCss(json)` — the same comparison `tokens:check` makes. `tokens.json` is imported as JSON (works without Node types).
- **Font stack:** `'Inter'` in tokens.json is emitted as `'Inter Variable', 'Inter', …` (the name `@fontsource-variable/inter` registers).
- **Contrast pairs** (both themes, all pass after the accent change): ink-primary and ink-secondary on page/raised/sunken; accent link text on page; accent-ink on accent and accent-strong; accent-strong on accent-soft (text, 4.5). Non-text 3:1: accent focus outline on page, accent Input focus border on raised. Light: label 5.07, link 5.00, hover 7.16, accent Tag 6.09.
- **Exception — Input resting border** (border-subtle on surface-sunken) is held to a recorded floor per theme: light 1.14 (actual 1.146; architecture rounds it to 1.15), **dark 1.51** — architecture.md says "dark passes every pair", but this non-text pair misses 3:1 in dark too. Same reason applies (label + sunken fill). The test also fails if the pair ever passes, so the exception gets removed. `ink-muted` (placeholder/disabled) is not tested, per the architecture.
- **Proved the guards bite:** hand-edited tokens.css → `tokens:check` exit 1 and generate-tokens.test fails with "stale"; reverting accent to `#ad6a4d` → contrast fails on link text and button label. Both restored.
- **Dev check:** Vite on a spare port served `main.tsx` importing the font, `tokens.css`, `global.css` in that order; `tokens.css` contains `--surface-page: #faf7f2`; `global.css` has `background: var(--surface-page)`; font CSS 200. Server stopped.
- **Not tested (for ui-reviewer):** ThemeToggle selected segment (surface-raised on surface-sunken track) is a state indicator not in the Contrast list.
